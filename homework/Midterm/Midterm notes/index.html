Chapter 01

Opening Note

前言

這次專案是網頁設計課程的期中專案，我想製作一個和校園生活有關的整合式筆記網站，因此將網站命名為 CampusHub.test Notes，並把它定位成一個「校園筆記本」。我希望把學生平常可能會使用到的功能集中在同一個平台，讓使用者可以快速查看社群、商店、信箱、校務、搜尋、輔助系統與排行榜等不同內容。

透過這次製作，我除了練習使用 HTML 建立網頁結構、使用 CSS 設計版面，也希望運用 JavaScript 增加互動效果，並學習如何在開始寫程式之前先整理網站架構。對我來說，這不只是做出一個畫面，而是練習把一個想法逐步整理成可以實際瀏覽的網站。

重點整理： CampusHub 的核心概念是把校園生活常用功能集中在同一個平台，讓學生能像翻閱校園手帳一樣找到需要的資訊。
Chapter 03

Project Overview

專案簡介

CampusHub.test Notes 是一個以校園生活為核心的筆記與資訊整合平台。網站希望用簡單、清楚的方式呈現不同校園功能，讓使用者進入首頁後，就能依照自己的需求前往對應的模組。

網站名稱中的 CampusHub 代表校園中心與校園資訊集合點，Notes 則代表筆記本，強調學習紀錄與資訊整理。網站不是只處理單一功能，而是以「學生常用功能集合」為核心，讓使用者可以像翻校園手帳一樣找到不同區塊。

設計理念： 版面要清楚、導覽要明顯、功能入口要容易理解，讓資訊多但不顯得混亂。
Chapter 04

System Structure

網站架構

本專案目前以 HTML、CSS 與 JavaScript 作為前端主要技術，並規劃使用 Vercel 將網站部署到線上。不同功能可以對應不同頁面或路徑，讓網站架構更清楚。資料部分目前可以先使用假資料或 JSON，未來如果功能更完整，再串接正式資料庫。

類型 技術或工具 用途
前端 HTML 建立網頁結構與內容層次
樣式 CSS 設計版面、配色與視覺效果
互動 JavaScript 製作按鈕、切換與資料渲染
部署 Vercel 將網站發布到線上供他人瀏覽
資料 假資料 / JSON / 未來資料庫 儲存筆記、文章與功能內容

後端功能目前仍屬於未來規劃，可擴充登入、發文、留言、訊息通知與管理員後台等功能。這樣的安排可以先把前端架構做好，再依照需求增加資料處理能力。

Chapter 06

Front-end Design

前端設計

6.1 版面設計

網站採用清楚的導覽列，並將導覽放在明顯的位置，讓使用者可以快速進入不同功能頁面。功能分區使用卡片式或區塊式設計，讓每一個模組彼此有區隔，頁面閱讀動線也更簡單，適合學生快速查找資料。

6.2 視覺風格

網站風格偏向校園筆記本與資訊整理平台，色彩以簡潔、柔和、清楚為主，避免太複雜的裝飾。設計重點放在資訊辨識度，希望讓網站看起來像一個學生專用的線上筆記空間。

6.3 使用者體驗

使用者不需要一開始就理解所有功能，可以透過導覽列慢慢探索。每個模組名稱都直接對應功能，搭配簡短說明，能降低使用者迷路的可能，也讓第一次進入網站的人比較容易理解整體架構。

設計重點： 先讓資訊容易找到，再加入視覺裝飾；清楚的導覽比複雜效果更重要。
Chapter 07

Interaction Plan

JavaScript 規劃

JavaScript 可以負責網站中的互動功能，讓頁面不只是靜態內容。以 CampusHub.test Notes 來說，可以先從簡單的切換與資料顯示開始，再逐步增加更完整的功能。

  • 切換頁面或不同功能區塊。
  • 載入假資料，將資料顯示在畫面上。
  • 顯示社群文章、商店商品與信箱通知。
  • 依照使用者輸入的關鍵字搜尋資料。
  • 將排行榜內容依積分或活躍度排序。
  • 點擊按鈕後顯示詳細內容或提示訊息。

這些功能可以讓我練習如何把資料與畫面連接起來，也能理解使用者操作網站時，程式需要如何回應。

Chapter 08

Data Format

資料格式

網站中的文章、公告或筆記可以先使用 JavaScript 物件陣列保存。以下是一筆校務公告的 JSON 結構範例： 

const posts = [
  {
    id: 1,
    title: "期中考提醒",
    category: "校務",
    content: "記得查看考試時間與地點",
    author: "系統公告",
    createdAt: "2026-06-03"
  }
];

使用固定欄位整理資料有以下好處：

  • 資料結構清楚，每筆內容都有相同的格式。
  • 方便使用 JavaScript 將資料渲染到畫面上。
  • 之後增加搜尋、分類或排序時比較容易處理。
  • 未來如果串接資料庫，也比較容易轉換與管理。
Chapter 09

Online Publishing

部署說明

本專案規劃部署在 Vercel。Vercel 可以讓前端網站快速發布到網路上，每次更新專案後，也能重新部署最新版本。使用線上網址後，老師或同學可以直接打開瀏覽，不需要先下載檔案或設定本機環境。

對學生專案來說，Vercel 的優點是操作方式相對簡單，也很適合用來展示作品。不過部署後仍需要檢查圖片、CSS、JavaScript 等檔案路徑是否正確，確保線上畫面和本機測試結果一致。

部署檢查： 上線後要重新測試頁面連結、檔案路徑、手機版顯示與互動功能。
Chapter 10

Learning Record

製作過程

10.1

一開始的規劃

我先思考學生在校園中常需要哪些資訊，例如公告、筆記、交易、訊息與搜尋功能，因此決定把這些功能集中在同一個網站。

10.2

製作畫面

我先建立網站首頁與導覽列，再依照不同功能建立頁面或區塊，讓整體架構更清楚，也方便之後逐步增加內容。

10.3

調整功能

在製作過程中，我會不斷檢查功能名稱是否清楚、按鈕是否容易理解、頁面排版是否適合閱讀，並依照測試結果調整。

10.4

學到的內容

這次製作讓我練習網站架構規劃、導覽列設計、頁面分區、前端資料呈現、部署到線上，以及如何將一個想法變成實際網站。

Chapter 11

Problems & Solutions

問題與解決

在規劃與製作網站時，我遇到的問題不只有程式語法，也包含功能分類、版面整理與部署測試。以下整理出幾個主要問題與處理方式。

遇到的問題 原因 解決方式
功能太多，不知道怎麼分類 一開始想放很多校園功能 先把功能分成社群、商店、信箱、校務等模組
頁面內容容易雜亂 每個區塊資訊量不同 使用導覽列與卡片式排版整理
不確定資料要怎麼放 還沒有正式資料庫 先使用假資料或 JSON 結構
部署後畫面可能和本機不同 線上環境與本機路徑不同 檢查路徑、重新部署並測試網址
使用者可能不理解功能 模組名稱不夠明確 使用清楚的標題與說明文字
Chapter 12

AI Assistance

AI 使用說明

本專案在規劃與撰寫過程中有使用 AI 輔助。AI 主要協助我整理網站架構、規劃功能模組、修飾報告內容，以及協助理解部分程式邏輯。不過網站主題、功能方向與最終內容仍由我自己決定與調整。

在使用 AI 的過程中，我也需要判斷建議是否符合自己的專案，而不是直接使用所有內容。這讓我學到，AI 可以成為整理想法與解決問題的工具，但最後仍需要自己檢查、修改與理解。

Chapter 13

Reflection

心得反思

透過這次專案，我發現做網站不只是把畫面做出來，還需要先思考使用者需求、功能分類、頁面動線與資料結構。CampusHub 這個專案讓我練習把校園生活中的不同資訊整理成一個平台，也讓我更理解網頁設計中的架構規劃與使用者體驗。

雖然目前功能還可以繼續擴充，但這次製作讓我對網站從無到有的過程有更清楚的認識。我也發現，先整理好功能與內容，再開始設計畫面，能讓後續製作更有方向。

「一個好用的網站，不只是功能很多，而是讓使用者知道自己現在在哪裡，也知道下一步可以去哪裡。」

Chapter 15

Conclusion

結論

CampusHub 是一個以校園生活為主題的整合式筆記網站。這次專案讓我練習網頁設計、架構規劃、功能分類與部署，也讓我了解一個網站需要同時考慮內容、操作方式與使用者需求。

雖然目前仍有可以改進的地方，但我已經建立出網站的基本方向。未來如果繼續加入登入、資料庫、互動與管理功能，CampusHub 就能逐步發展成更完整的校園服務平台。
